# Ink and Bone mark pipeline

Every mark and every export in `out/` is generated by `generate_marks.py`. Nothing is hand-placed. Geometry is defined once per mark, on a 96 by 96 grid, stroke 7, round caps and joins, true arcs, with optically simplified variants for 24 and 16 pixels.

## Run

From the repository root, after following the locked bootstrap in
`design/brand/BRAND-SURFACES.md`:

    bash design/brand/run-mark-pipeline.sh              # public targets
    bash design/brand/run-mark-pipeline.sh helios zest  # selected targets

Do not install ad hoc dependencies. Direct requirements are declared in
`requirements.in`; the full graph and distribution hashes are in
`requirements.lock`. Run `bash design/brand/check-toolchain.sh` first.

## Distribute to consumers

Consumer copies are declared in `consumers.public.json`. The distributor is
read-only by default; `--check` is shown explicitly for clarity:

    .venv/bin/python design/marks/distribute_assets.py --check

Exit 0 means all declared assets and generated provenance match, exit 1 means
updates are pending, and exit 2 is a safety or validation failure. Review
every reported path. Use `--apply` only as a separate, explicitly approved
step after generated outputs are final and affected consumer worktrees have
been confirmed clean. Apply mode refuses a dirty canonical source by default
and validates trusted predecessor provenance. `--allow-dirty-source` is an
exception requiring explicit owner approval, and its use is recorded. The
tool never builds, commits, pushes, deploys, or verifies runtime caches.
Private consumers use a separate private-only manifest described in the
private operations extension.

## What each project gets

| Folder | Contents |
|---|---|
| `svg/` | mark.svg and mark-light.svg masters, mark-24 and mark-16 variants in both themes, mark-mono.svg |
| `pdf/` | mark.pdf (light palette, for print), mark-dark.pdf |
| `png/` | 1024 to 16, transparent in both palettes, on page #0B0C0D, on paper #F5F5F3 |
| `jpeg/` | 1024 and 512 on both grounds |
| `wordmark/` | horizontal and stacked lockups in Karpal Geometric, SVG, PDF, PNG, both themes |
| `macos/` | AppIcon.iconset, AppIcon.icns, menu bar `*-template.png` at 1x 2x 3x (black with alpha) |
| `ios/` | full AppIcon.appiconset with Contents.json, apple-touch-icon 180 |
| `watchos/` | current 38-49 mm watch AppIcon.appiconset, complications (circular, extra large, graphic corner, graphic circular) as white monochrome templates |
| `web/` | favicon.ico (16 32 48), favicon.svg (theme adaptive), opaque PWA icons at 192 and 512 plus a safe-zone-tested 512 maskable icon, README banners 1400x400 dark and light, social preview 1280x640 |
| `appstore/` | AppStore-1024.png, no alpha, no rounded corners |
| `contact-sheet-<project>.png` | one-glance review sheet (the unsuffixed `contact-sheet.png` name is legacy; the pipeline deletes it on rebuild) |

## Rules encoded here

Sizes 48 and up use the master geometry, 20 to 47 use the 24 variant, below 20 the 16 variant. One accent per mark, category colour only. Grain never behind small type; banners autoscale long names instead of clipping. Shields and label hexes stay in `../brand/brand-tokens.json`.

## macOS-only step

The `.icns` files are generated cross-platform by icnsutil. To rebuild natively on the Mac:

    iconutil -c icns out/<project>/macos/AppIcon.iconset -o AppIcon.icns

## Private

Private source and derivatives use the gitignored `private_marks.py` and
`out/private/` paths. The generator is public-only by default and never loads
an adjacent overlay implicitly. Private generation requires explicit overlay
and inclusion flags governed by the tracked private operations extension.
Never publish or link either path; see BRAND-SURFACES.md, INCIDENT 2026-08-19.
